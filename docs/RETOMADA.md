**Como trabalhar (regras do Kenidy):**
- Uma mudança por versão. Commit em português: `vX.Y.Z: o que mudou`. Subir `MARKETING_VERSION` e `CURRENT_PROJECT_VERSION` em `project.yml` (versão com no máximo 3 números). O trabalho vive no `main` (ramos antigos já unidos podem restar no GitHub; o proxy não deixa apagar ramos remotos, o Kenidy apaga pela página de ramos): criar ramo `vX.Y.Z`, empurrar com `git push origin HEAD:refs/heads/vX.Y.Z` e disparar o CI no ramo (o CI só roda sozinho no `main`): para o IPA de teste, `build.yml`; **para o TestFlight (o que vale agora), `gh api -X POST repos/Kenidy-WS/Ei-Clip-ios/actions/workflows/testflight.yml/dispatches -f ref=vX.Y.Z`** (`gh workflow run` falha no proxy); acompanhar até ficar verde (12 a 16 min). Para unir: `git merge --ff-only refs/heads/vX.Y.Z` (as tags têm o mesmo nome do ramo; o nome puro pega a tag), e apagar o ramo local depois. Tags e releases ficam para sempre.
- Cada entrega em 4 partes: (a) o que mudou, (b) testes numerados no iPhone (pelo app TestFlight: o Kenidy atualiza para a build nova), (c) o que copiar do Diagnóstico, (d) próximo passo. Com o link do IPA (`https://github.com/Kenidy-WS/Ei-Clip-ios/releases/download/vX.Y.Z/EiClip-vX.Y.Z.ipa`) e "AÇÃO SUA" em passos numerados. Lembrar de conferir a versão no topo do Diagnóstico (já houve teste com IPA antigo instalado por engano).
- **Esperar o "pode seguir" do Kenidy antes de qualquer versão nova.** Só marcar "Versão estável" no STATUS (e unir ao `main`) quando ele aprovar uma versão testada.
- Voz e sessão de áudio (área protegida) vão sozinhas numa versão.
- Decidir pela capacidade que o aparelho informa, nunca pelo modelo; todo caminho novo mantém o atual como reserva e registra o motivo no Diagnóstico.
- Textos do usuário só em `Engine/Textos.swift`, tom formal e curto (exceção: título e frases da ação do App Intents ficam como literais no arquivo da ação).
- Português simples, listas curtas (ele lê no celular), tratando por "você". Não lembrar que o app expira em 7 dias.
- Commit só de documentos: `[skip ci]` no fim. Se o trabalho `ipa` do CI aparecer "cancelled" sem passos, foi fila de máquina: `gh run rerun <id> --failed`.
